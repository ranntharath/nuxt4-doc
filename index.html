Introduction

Welcome to the Nuxt 4 documentation. Nuxt is the full-stack framework for Vue, designed to make building Vue applications easier, faster, and more powerful.

By default, Vue.js is a client-side framework used to build UI components. Nuxt wraps Vue.js to provide a robust, convention-over-configuration architecture that lets you build complete, SEO-friendly web applications.

Nuxt provides routing, data fetching, SEO, server-side rendering (SSR), and more right out of the box, all utilizing a simple file-based structure.
Get Started

What is Nuxt?

Nuxt is a framework built on Vue.js. Instead of manually configuring complex build tools, routers, and state management, Nuxt provides these features for you automatically.

📄 File-based routing

Routes are created automatically from your app/pages/ directory without manual configuration.

🔄 Data fetching

Built-in useFetch handles server and client data efficiently, preventing double-fetching.

🖥️ Server-Side Rendering

Fast initial loads and perfect SEO right away, rendering Vue on the server.

🌐 API routes

Build your backend API directly inside the server/ folder using the Nitro engine.

🔍 SEO support

Easy management of head tags and meta descriptions out-of-the-box.

📦 Auto imports

Vue APIs, composables, and components are available globally without writing imports.

🧩 Layouts & middleware

Wrap pages in shared UI and intercept navigation for things like authentication easily.

⚡ Performance

Powered by Vite and Nitro for lightning-fast build times and runtime execution.

Vue vs Nuxt

While Vue is the core rendering library, Nuxt provides the surrounding architecture necessary to build a production-ready application.

Feature Vue.js Nuxt 4
Scope UI framework Full-stack framework
Routing Manual setup Automatic file-based
Rendering Client-side SSR / SSG / Hybrid built-in
Configuration Requires manual wiring Zero-config conventions
Simple Idea: Use Vue to build your UI components. Use Nuxt to build your complete web application.

Nuxt gives you conventions and tools so you write less configuration code and focus more on features.

Without Nuxt (Vue Setup)

Vue ├── Vue Router ├── Pinia ├── Axios / Fetch ├── SSR config ├── SEO config └── Other manual wiring...

With Nuxt

Bottom Line: Nuxt eliminates hours of manual configuration. By providing a standard folder structure and built-in features, your team can start building the actual application from day one without worrying about setting up tools.

Creating a new Nuxt 4 project is incredibly easy. You just need Node.js installed on your machine.

Run the following command in your terminal to create a new Nuxt project:

During installation, the CLI will ask you a few questions:

  • Which template? Choose minimal for a clean starter.
  • Package Manager: It is recommended to choose npm.

  • Browse and install modules? Choose No for now.

Structure

Project Structure

Nuxt 4 introduces a refined directory structure, utilizing an app/ directory by default to cleanly separate your frontend code from configuration and server logic.

◬ my-nuxt-app
Copy
my-nuxt-app/ ├── app/ // Frontend Vue application │ ├── pages/ │ ├── components/ │ ├── layouts/ │ ├── middleware/ │ └── composables/ ├── server/ // Backend API and Nitro routes ├── shared/ // Types/utils shared between app & server ├── public/ // Static assets └── nuxt.config.ts // Main configuration file

📦 The app/ Directory

This is the heart of your frontend application. Nuxt 4 moved all the standard Vue files (like pages, components, layouts, plugins, and composables) inside this single directory. This clean separation ensures your frontend code doesn't mix with backend logic, making large projects much easier to navigate and maintain.

🌐 The server/ Directory

Powered by the blazing-fast Nitro engine, this folder allows you to build a complete backend API directly within your Nuxt project. Any file you create in server/api/ automatically becomes an API endpoint. You can connect to databases, handle authentication, and write server-side middleware here.

🤝 The shared/ Directory

A highly requested feature in Nuxt 4! The shared/ directory is used for code that needs to be accessed by both your Vue frontend and your Nitro backend. It is the perfect place to store shared TypeScript interfaces, Zod validation schemas, and common utility functions, ensuring complete type safety across your entire stack.

⚙️ The nuxt.config.ts File

This single file controls your entire application's behavior. Instead of juggling separate configuration files for Webpack/Vite, PostCSS, or Vue Router, you handle everything here. You can easily register Nuxt modules (like Tailwind or Pinia), define global environment variables, and configure rendering modes (SSR, SPA, or SSG) with just a few lines of code.

Structure

Inside app/ Directory

The app/ directory contains the core of your Vue.js frontend application.

📄 pages/

Vue components here automatically become your application's URLs (routes). No router config needed.

🧩 components/

Reusable Vue UI components. Nuxt auto-imports these so you can use them directly in templates.

🖼️ layouts/

Wrappers for your pages (like a Header and Footer) that persist across route changes without re-rendering.

🧠 composables/

Reusable stateful logic and Vue composables. Auto-imported globally for use anywhere in your app.

🛡️ middleware/

Route guards. Run code before navigating to a particular page (e.g., redirecting unauthenticated users).

Structure

Root Directories

Outside of the app/ directory, Nuxt manages your backend, shared code, and static assets.

🌐 server/

Powered by the Nitro engine. Create backend APIs, server routes, and server middleware completely separate from the Vue app.

🤝 shared/

A new feature in Nuxt 4. Code placed here is auto-imported in both your Vue app and server API.

📁 public/

Static files (favicon.ico, robots.txt, images) that are served directly at the root URL without processing.

⚙️ nuxt.config.ts

The central configuration file where you register modules, configure build tools, and set global meta tags.

Routing

One core feature of Nuxt is the file system router. Every Vue file inside the app/pages/ directory creates a corresponding URL (or route) that displays the contents of the file.

No need to manually create a Vue Router configuration. Nuxt generates it under the hood.

◬ Directory Mapping
app/pages/ ├── index.vue // Maps to -> / ├── about.vue // Maps to -> /about └── products.vue // Maps to -> /products

🏠 Home Page (index.vue)

The index.vue file automatically maps to the root URL (/). This is your homepage.

📄 app/pages/index.vue
Copy
<template> <div> <h1>Welcome to the Home Page</h1> </div> </template>
localhost:3000/

Welcome to the Home Page

ℹ️ About Page (about.vue)

Any other file name becomes a route with that exact name. about.vue becomes the /about URL.

📄 app/pages/about.vue
Copy
<template> <div> <h1>About Us</h1> </div> </template>
localhost:3000/about

About Us

🛍️ Products Page (products.vue)

Similarly, products.vue creates the /products URL.

📄 app/pages/products.vue
Copy
<template> <div> <h1>Our Products</h1> </div> </template>
localhost:3000/products

Our Products

Enabling the Router (app.vue)

Crucial Step: To enable page routing, you must add the <NuxtPage /> component inside your main app.vue file. This component acts as an outlet, telling Nuxt exactly where to display the current page's content.

By default, a new Nuxt project comes with a Welcome screen. You need to replace it with <NuxtPage /> to see your own pages:

⚠️ app.vue
Copy
<template> <div> <!-- Displays the active page based on the URL --> <NuxtPage /> </div> </template>

❓ What is it?

<NuxtPage /> is a built-in Vue component provided by Nuxt. It acts as a dynamic placeholder.

⚙️ How does it work?

When a user visits a URL (like /about), Nuxt looks inside the app/pages/ folder, finds about.vue, and injects its content directly where <NuxtPage /> is placed.

⚠️ Why is it needed?

Without it, Nuxt doesn't know where on the screen to render your pages. By using this placeholder, you can easily place global UI elements—like a Navbar above it, and a Footer below it—inside app.vue, and they will persist across all pages.

Dynamic Routes

Nuxt supports dynamic routes using square brackets [ ] in the filename.

🃏 The Wildcard Analogy:

Imagine you have 1,000 products. Instead of creating 1,000 separate files (like 1.vue, 2.vue, etc.), you create one single file named [id].vue. The brackets tell Nuxt: "Hey, whatever value the user types in the URL here, catch it and call it id".

/products/123
➔
[id].vue (id = '123')
/products/apple
➔
[id].vue (id = 'apple')
◬ Directory Mapping
Copy
app/pages/ └── products/ └── [id].vue // Maps to -> /products/1, /products/2, etc.

Accessing Route Parameters

Inside your page, you can access the dynamic parameter (e.g., id) using the useRoute() composable.

📄 app/pages/products/[id].vue
Copy
<script setup lang="ts"> const route = useRoute() // When visiting /products/123, this logs '123' console.log(route.params.id) </script> <template> <div> <h1>Product ID: {{ route.params.id }}</h1> </div> </template>
localhost:3000/products/123

Product ID: 123

Nested Routes

Sometimes, you want multiple pages to share the same layout structure (like a common sidebar or dashboard menu). Instead of copying that code into every file, Nuxt allows you to create Nested Routes.

🖼️ The Picture Frame Analogy:

Think of the Parent Component as a picture frame. The frame stays exactly the same on the wall, but you can swap out the Child Pages (the pictures inside the frame) just by navigating to a different URL.

parent.vue
<NuxtPage />
child-one.vue
➔
parent.vue
<NuxtPage />
child-two.vue

⚙️ How to set it up (3 Simple Steps):

  1. Create a parent file (e.g., parent.vue).
  2. Create a folder with the exact same name (e.g., parent/).
  3. Put your child files inside that folder (e.g., child-one.vue).
◬ Directory Mapping
Copy
app/pages/ ├── parent.vue // Parent wrapper └── parent/ ├── index.vue // Maps to -> /parent ├── child-one.vue // Maps to -> /parent/child-one └── child-two.vue // Maps to -> /parent/child-two
The parent.vue file must contain the <NuxtPage /> component for the child views to be rendered inside it.
📄 app/pages/parent.vue
Copy
<template> <div style="border: 2px dashed #00DC82; padding: 20px;"> <h1>Parent Component</h1> <!-- Child pages will be injected here! --> <NuxtPage /> </div> </template>
📄 app/pages/parent/child-one.vue
Copy
<template> <div style="background: #f1f5f9; padding: 20px;"> <h2>Child One Content</h2> </div> </template>
localhost:3000/parent/child-one

Rendering

Client-Side Rendering (CSR)

Before understanding Nuxt, we must understand how standard Vue.js or React applications work. This is called Client-Side Rendering (CSR).

📱 How CSR Works

When a user visits a CSR website, the server sends back an almost empty HTML document (just an empty div with id 'app') along with a massive JavaScript file. The user's browser (the client) has to download this JavaScript, execute it, and then construct the UI.

💻
Browser requests URL
➔
📄
Server sends Blank HTML + JS
➔
⏳
Browser builds the UI

What does "Blank HTML" look like?

If you view the source code of a standard Vue.js or React website, you will usually only see this:

📄 index.html (What Google sees)
<!DOCTYPE html> <html> <head> <title>My App</title> <script defer src="/assets/main-bundle.js"></script> </head> <body> <!-- The entire website is injected here by JavaScript! --> <div id="app"></div> </body> </html>

Why use CSR?

⚡ Fast Navigation

Navigate between pages without a full page reload.

✨ Better User Experience

The app feels more like a native application.

🖱️ Interactive UI

Great for: Buttons, Forms, Modals, Dashboards, Real-time updates.

📉 Less Server Rendering Work

The browser handles most of the rendering.

🔒 Good for Private Applications

Such as: Admin dashboard, Student management system, Employee system, Internal company tools.

🔄 Dynamic Data Updates

You can fetch data and update only part of the page.

The Problems with CSR

⏳ Slower First Load

The browser must download and run massive JavaScript files before showing anything.

🔄 Loading States

You must show spinners or skeletons while data is being fetched from APIs.

📱 Heavy on User Devices

More work for the user's device — especially older/slower phones and computers.

❌ Poor SEO

SEO is much less straightforward. Bots often see a blank page without content.

⚠️ JS Dependency

JavaScript is absolutely required for the application to fully function.

📦 Bundle Size

Large JavaScript bundles can severely hurt performance.

Rendering

Server-Side Rendering (SSR)

To solve the massive problems with CSR, Nuxt introduces Server-Side Rendering (SSR).

🌍 How SSR Works

When a user visits a Nuxt website, Nuxt's Nitro Server acts like a browser on the server. It builds the Vue components, fetches data from the database, constructs a fully complete HTML document, and sends it to the user. The browser receives a finished page.

💻
Browser requests URL
➔
⚡
Nitro builds HTML instantly
➔
🚀
Browser receives Full UI

What does "Full HTML" look like?

If you view the source code of a Nuxt SSR website, you will see all of your content already there:

📄 index.html (What Google sees)
<!DOCTYPE html> <html> <head> <title>My Awesome Nuxt Blog</title> <meta name="description" content="Read my amazing articles" /> </head> <body> <!-- The content is already here! Perfect for SEO! --> <div id="__nuxt"> <header> <h1>Welcome to my Blog</h1> </header> <main> <article>Why Nuxt 4 is amazing...</article> </main> </div> </body> </html>

Why use SSR?

📈 Perfect SEO

Google's bots see fully populated HTML. Crucial for E-commerce and blogs.

🚀 Faster Initial Paint

Users see the content instantly, with no white screen while waiting for JS.

🔗 Social Media Previews

Links shared on Facebook/Twitter correctly display titles and images.

🔋 Better for Low-End Devices

The server does the heavy lifting, saving battery and CPU on cheap phones.

🛡️ Secure Data Fetching

API keys and database credentials can be securely hidden on the server.

🌍 Better for Slow Networks

HTML is small and downloads quickly, providing a resilient user experience.

The Problems with SSR

💵 Higher Hosting Costs

Requires an active Node.js server running 24/7, which costs money.

🐢 Slower Time to Interactive

Users see the UI instantly, but buttons might not work until Hydration finishes.

🏋️ High Server Overhead

High traffic forces the server to build HTML repeatedly. Caching is mandatory.

🧠 Added Complexity

Developers must carefully manage code to avoid "window is undefined" errors on the server.

⏳ Slower Initial Response

The server must fetch data and render the UI before it can send the first byte of HTML.

🔧 Harder to Deploy

Deploying a Node app requires more configuration than uploading static CSR files.

Rendering

CSR vs SSR: Summary

Now that we understand both CSR and SSR, let's look at a direct comparison before introducing Nuxt's ultimate solution.

Feature Client-Side (CSR) Server-Side (SSR)
Initial Page Load ⏳ Slow (Blank screen first) 🚀 Fast (Instant content)
SEO (Search Engines) ❌ Poor (Bots see blank HTML) ✅ Excellent (Full HTML)
Navigation Speed ⚡ Very Fast (No refresh) 🐢 Slower (Requires refresh)
Hosting Costs 💵 Free / Cheap (Static files) 💸 High (Requires Server/Node)
Server Load 📉 Low (Browser does the work) 🏋️ High (Server builds every page)
Rendering

Universal Rendering (Hydration)

So, SSR is perfect, right? Not entirely. If we only sent static HTML from the server, the website wouldn't be interactive (buttons wouldn't work, no Vue reactivity). This is where Nuxt does magic.

💧 The Best of Both Worlds: Hydration

Nuxt uses Universal Rendering. It does both SSR and CSR seamlessly:

  1. Step 1 (SSR): Nuxt builds the page on the server and sends HTML to the user so they see the content instantly.
  2. Step 2: In the background, the browser downloads the Vue JavaScript.
  3. Step 3 (Hydration): Vue "wakes up" the static HTML and attaches interactivity (click listeners, state, reactivity) to the page.
  4. Step 4 (CSR): When the user clicks a link to go to a new page, Nuxt acts like standard Vue (CSR). It doesn't ask the server for a full HTML document again, it just swaps components instantly on the client.
Nuxt gives you the SEO and Speed of SSR, with the Smooth Interactivity of CSR.
